3. TASK: Motor control redesign (OctoPrint layout + um micro-steps) — PLANNING
--------------------------------------------------------------------------------
Status: exploration complete, design/plan not finalized (paused when user pivoted).
Key facts gathered (for when this resumes):
- Motor iface: devices/motor_base.py. Position NamedTuple (.x_mm/.y_mm/.z_mm, mm).
  move_relative(dx_mm,dy_mm,dz_mm), move_to(x,y,z), home(axes), zero_position(),
  stop(), move_to_center(). Single-axis jog is the norm.
- limits = SoftwareLimits dataclass (x_min..z_max, flat floats, mm). Config envelope
  (devices.yaml): X -300..0, Y -300..0, Z -400..0 mm.
- GRBL native resolution: X/Y microstep = 0.0125 mm (12.5 um); Z = 0.0025 mm (2.5 um).
  Full-step detent X/Y 0.2mm, Z 0.04mm. snap_mode 'off' by default.
  => IMPORTANT: a um interface is useful, but 1 um steps are finer than X/Y hardware
     can resolve (12.5 um). Preset um choices should respect this.
- Current motor_panel.py is a 2-col +/- grid, NOT an OctoPrint cross. Jog step
  spinbox 0.001-10.0 mm, default 2 decimals (so 1um not reachable at default precision).
- MUST PRESERVE on redesign: MotorPanel(motor, parent=None) ctor; set_as_scan_start
  signal (-> scan_panel.set_start_position); shutdown(); 500ms threaded _PositionPoller
  with set_paused; _run_async/_MotorTask worker; _motion_widgets disable-during-move
  (STOP excluded, runs on GUI thread, calls motor.stop() directly — guarded by
  test_grbl_stop_sends_jog_cancel); single _on_position_updated sink that formats
  labels AND drives stage_view.set_position(x,y,z).
- Style: gui/style.py has light/dark theme, ACCENT #2d7ff9, WARN_RED #c0392b (inline
  danger styling), QGroupBox cards, suffix-carrying QDoubleSpinBox (real u glyph),
  emoji-in-text buttons. No shared mm<->um helper exists (ad-hoc *1000 elsewhere).
- No GUI-level tests touch MotorPanel; only device-level test_motor_grbl_mock.py.
