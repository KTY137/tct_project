Open safety question for Kaya: the ratified envelope is approved once per run. For a sequence, either (a) arming approves ONE combined envelope spanning every queued routine (max HV, total travel, total points — one hold-3-s for the night), or (b) each routine re-arms and the sequencer pauses at each boundary until you confirm. (a) is the true unattended workflow; (b) is stricter. Abel recommends (a) with the combined envelope text listing every routine by name — same re-validation machinery, and Abort/kill remain one-tap throughout.

Decisions

  1. One accent per row. Nominal rows (loops, settle, acquire, save) are grey and quiet; motion rows amber; HV rows red. The audit's rainbow (amber/cyan/pink pills per row + red confirm slabs) collapses into a readable hazard map of the recipe.
  2. CONFIRM pill is dead. A per-row confirm contradicts the ratified once-per-run envelope. Hazard rows carry a read-only glyph meaning "enumerated in the armed envelope" — every affordance lives in the aside.
  3. Behaviors become eyebrows. snake, settle-time, step width move into tiny mono eyebrows inside the row — the qty chip holds exactly one number.
  4. Latch flow untouched. Validate → Dry run (unlocks arming) → hold-3-s Arm over the full envelope text → armed ~10 s → Execute. This is ratified safety flow; v5 only re-materializes it.
  5. Clipping bug fixed structurally. The recipe header no longer overlaps the first row (the live audit shows PREFLIGHT half-cut) — the header is a card .hd, rows start below it.
